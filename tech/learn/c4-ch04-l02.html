어셈블리어

CPU가 실제로 읽는 기계어는 0과 1의 나열이라 사람이 읽기 어렵습니다. 그래서 명령어를 MOV, ADD 같은 짧은 영어 약어로 적는 어셈블리어를 씁니다. 어셈블리어 한 줄은 기계어 명령어 하나와 대응합니다.

이 챕터에서는 레지스터 A, B 두 개를 가진 가상의 CPU를 씁니다. 가상의 CPU 명령어: MOV A, n (A에 n 넣기) · ADD A, B (A ← A + B) · SUB A, n (A ← A − n) · LOAD A, [주소] (메모리 값을 A로) · STORE [주소], A (A를 메모리로) · JMP k (k번 줄로 이동) · JNZ k (바로 앞 계산 결과가 0이 아니면 k번 줄로 이동).

문제 1

MOV A, 7 다음에 SUB A, 2를 실행하면 A는 얼마일까요?

레지스터 값 따라가기

프로그램을 이해하는 가장 좋은 방법은 줄마다 레지스터 값을 적어 가는 것입니다. 예를 들어 1: MOV A, 3 → A = 3, 2: MOV B, 4 → B = 4, 3: ADD A, B → A = 7, 4: ADD A, B → A = 11입니다.

ADD A, B는 A만 바꾸고 B는 그대로 둡니다. 결과가 들어가는 쪽(여기서는 A)과 읽기만 하는 쪽을 구별해야 합니다.

예제

1: MOV A, 10 / 2: MOV B, 5 / 3: ADD A, B / 4: SUB A, 3 을 실행하면 A와 B는?

  1. 1: A = 10, 2: B = 5입니다.
  2. 3: A = 10 + 5 = 15입니다.
  3. 4: A = 15 − 3 = 12, B는 그대로 5입니다.

답: A = 12, B = 5

메모리와 주고받기

레지스터는 몇 개뿐이라 대부분의 데이터는 메모리에 있습니다. LOAD A, [100]은 메모리 100번지의 값을 A로 가져오고, STORE [100], A는 A의 값을 메모리 100번지에 씁니다.

그래서 메모리의 두 값을 더해 다시 메모리에 저장하려면 '불러오기 → 계산 → 저장' 세 단계가 필요합니다. 이처럼 계산은 레지스터에서만 하고 메모리와는 불러오기·저장으로만 주고받는 구조를 로드-스토어 구조라고 합니다.

예제

메모리 100번지에 5, 101번지에 9가 있습니다. 1: LOAD A, [100] / 2: LOAD B, [101] / 3: ADD A, B / 4: STORE [102], A 를 실행하면 102번지의 값은?

  1. A = 5, B = 9입니다.
  2. A = 5 + 9 = 14입니다.
  3. 102번지에 14가 저장됩니다.

답: 14

사람은 보통 C, 파이썬 같은 고급 언어로 프로그램을 씁니다. 'c = a + b' 한 줄은 컴파일러가 LOAD, LOAD, ADD, STORE 같은 여러 기계어 명령어로 바꿉니다. 결국 모든 프로그램은 이런 단순한 명령어의 나열로 실행됩니다.

예제

메모리 50번지에 3이 있습니다. 1: LOAD A, [50] / 2: MOV B, 3 / 3: ADD A, B / 4: ADD A, B / 5: STORE [51], A 를 실행하면 51번지의 값은?
