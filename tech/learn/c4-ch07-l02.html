계층과 패킷

컴퓨터 · 7. 네트워크 기초 · 레벨1 · 약 15분 · 문제 16개

이 레슨 풀어 보기연습 문제에세이 과제

일을 층으로 나누기

네트워크 통신은 할 일이 많습니다. 신호를 보내고, 옆 장치에 전달하고, 먼 곳까지 길을 찾고, 빠짐없이 순서대로 받고, 웹 페이지 같은 서비스를 제공해야 합니다. 이를 층(계층)으로 나누어 각 층이 자기 일만 맡게 합니다.

인터넷은 TCP/IP 모델의 4계층을 씁니다. 아래부터 링크 계층(이웃 장치에 전달, 이더넷·Wi-Fi), 인터넷 계층(먼 곳까지 길 찾기, IP), 전송 계층(프로그램 사이의 믿을 만한 전달, TCP·UDP), 응용 계층(서비스, HTTP·DNS)입니다.

문제 1

TCP/IP 4계층을 아래(하드웨어 쪽)부터 배열하세요.

패킷

큰 데이터는 작은 조각(패킷)으로 나누어 보냅니다. 조각마다 따로 길을 찾아가므로 한 길이 막혀도 다른 길로 갈 수 있고, 여러 사람이 선을 나누어 쓸 수 있습니다. 받는 쪽에서 조각을 다시 맞춥니다.

이더넷에서 한 번에 보낼 수 있는 데이터는 보통 1500바이트 정도입니다. 그래서 1 MB 파일은 수백 개의 패킷으로 나뉘어 갑니다.

예제

15 000바이트 데이터를 패킷 하나에 1500바이트씩 담으면 패킷 몇 개가 필요할까요?

  1. 15 000 ÷ 1500 = 10개입니다.

답: 10개

문제 2

데이터를 작은 조각으로 나누어 보낼 때 그 조각을 ＿＿＿이라고 합니다.

문제 3

6000바이트 데이터를 패킷 하나에 1500바이트씩 담으면 패킷 몇 개가 필요할까요?

문제 4

4000바이트 데이터를 패킷 하나에 1500바이트씩 담으면 패킷 몇 개가 필요할까요?

문제 5

먼 곳까지 길을 찾아 패킷을 전달하는 계층은 ＿＿＿ 계층입니다.

캡슐화

보내는 쪽에서는 위 계층의 데이터에 각 계층이 자기 정보를 담은 머리말(헤더)을 붙여 아래로 내려보냅니다. 응용 데이터 + TCP 헤더 + IP 헤더 + 이더넷 헤더 순으로 겹겹이 싸이는데, 이를 캡슐화라고 합니다. 받는 쪽은 아래 계층부터 헤더를 하나씩 벗겨 위로 올립니다.

헤더도 선을 통해 보내야 하므로 실제 데이터보다 많은 바이트가 오갑니다. 예를 들어 TCP 헤더 20바이트, IP 헤더 20바이트면 패킷마다 40바이트가 더 붙습니다.

예제

데이터 1460바이트에 TCP 헤더 20바이트, IP 헤더 20바이트를 붙이면 IP 패킷은 몇 바이트일까요?

  1. 1460 + 20 + 20 = 1500바이트입니다.
  2. 이더넷 한 프레임에 꼭 맞는 크기입니다.

답: 1500바이트

문제 9

받는 쪽은 ＿＿＿ 계층부터 헤더를 하나씩 벗겨 위로 올립니다.

OSI 7계층

교과서에서는 네트워크를 7계층으로 나눈 OSI 모델도 자주 봅니다. 아래부터 물리, 데이터 링크, 네트워크, 전송, 세션, 표현, 응용 계층입니다. TCP/IP의 링크 계층이 OSI의 1~2계층, 인터넷 계층이 3계층, 전송 계층이 4계층, 응용 계층이 5~7계층에 대응합니다. 스위치를 'L2 장치', 라우터를 'L3 장치'라고 부르는 것도 이 번호에서 왔습니다.

정리: TCP/IP 4계층(링크·인터넷·전송·응용), 패킷(약 1500 B)과 올림 계산, 캡슐화와 헤더, 헤더 오버헤드, OSI 7계층과의 대응(스위치 L2, 라우터 L3)

문제 10

OSI 모델에서 라우터가 주로 일하는 네트워크 계층은 몇 계층일까요?

예제

데이터 1 460 000바이트를 패킷마다 데이터 1460바이트, 헤더 40바이트로 보내면 실제로 오가는 바이트는?

  1. 패킷 수 = 1 460 000 ÷ 1460 = 1000개입니다.
  2. 헤더 = 1000 × 40 = 40 000바이트입니다.
  3. 합계 1 500 000바이트입니다.

답: 1 500 000바이트
