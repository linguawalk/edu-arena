라우팅, TCP와 UDP

컴퓨터 · 8. 인터넷 원리 · 레벨1 · 약 15분 · 문제 16개

이 레슨 풀어 보기연습 문제에세이 과제

여러 라우터를 거쳐서

패킷은 목적지까지 여러 라우터를 거칩니다. 라우터 하나를 지나는 것을 홉(hop)이라고 합니다. 라우터는 자기 라우팅 표를 보고 목적지 네트워크로 가려면 다음에 어느 라우터로 넘겨야 하는지만 정합니다. 전체 길을 아는 라우터는 없습니다.

길이 잘못 설정되어 패킷이 영원히 돌지 않도록, IP 헤더에는 TTL 값이 있습니다. 라우터를 지날 때마다 1씩 줄고 0이 되면 패킷을 버립니다.

문제 1

TTL 64로 출발한 패킷이 라우터 12개를 지나면 TTL은 얼마일까요?

포트 번호

IP 주소는 컴퓨터를 가리키지만, 그 컴퓨터 안의 어느 프로그램에게 줄지는 포트 번호로 정합니다. 포트는 16비트로 0~65 535입니다.

잘 알려진 서비스는 포트가 정해져 있습니다. 웹(HTTP) 80, 암호화된 웹(HTTPS) 443, DNS 53번입니다. IP 주소가 아파트 주소라면 포트 번호는 호수와 같습니다.

예제

브라우저가 https://tech-arena.org에 접속하면 서버의 몇 번 포트로 연결할까요?

  1. https는 암호화된 웹입니다.
  2. HTTPS의 기본 포트는 443입니다.

답: 443

TCP와 UDP

전송 계층에는 두 규약이 있습니다. TCP는 연결을 맺은 뒤 보내고(세 번의 주고받기로 연결: 3-way handshake), 받는 쪽이 받았다고 확인 응답을 보내며, 확인이 오지 않은 패킷은 다시 보냅니다. 순서 번호로 순서도 맞춥니다. 웹, 이메일, 파일 전송처럼 빠짐없이 받아야 하는 곳에 씁니다.

UDP는 연결 없이 그냥 보내고 확인하지 않습니다. 몇 개가 사라질 수 있지만 가볍고 빠릅니다. 실시간 영상 통화, 온라인 게임, DNS처럼 늦게 오는 것보다 빨리 오는 것이 중요한 곳에 씁니다.

예제

영상 통화에서 잃어버린 패킷을 TCP처럼 다시 보내면 어떻게 될까요?

  1. 다시 보낸 패킷은 이미 지나간 순간의 영상입니다.
  2. 기다리느라 화면과 소리가 멈칫거립니다.
  3. 그래서 영상 통화는 조금 잃더라도 UDP로 계속 보냅니다.

답: 지연이 커져 오히려 나빠진다

문제 9

TCP 연결을 맺을 때 주고받는 메시지는 몇 번일까요?

경로 확인

traceroute(윈도우는 tracert) 명령은 TTL을 1, 2, 3, …으로 늘려 가며 패킷을 보내, 각 라우터가 TTL이 0이 되어 버렸다고 알려 오는 메시지로 경로의 라우터를 하나씩 보여 줍니다. TTL을 영리하게 이용한 도구입니다.

정리: 홉과 라우팅 표(다음 라우터만 정함), TTL(홉마다 1 감소, 0이면 버림), 포트 번호(16비트, HTTP 80·HTTPS 443·DNS 53), TCP(연결·확인·재전송·순서)와 UDP(빠름·확인 없음)

문제 10

TTL을 늘려 가며 보내 경로의 라우터를 하나씩 알아내는 명령은 ＿＿＿입니다.

예제

TTL 5로 보낸 패킷이 목적지까지 라우터 8개를 거쳐야 한다면 어떻게 될까요?

  1. 라우터마다 TTL이 1씩 줄어 다섯 번째 라우터에서 0이 됩니다.
  2. 그 라우터가 패킷을 버립니다.
  3. 목적지에 닿지 못합니다.

답: 다섯 번째 라우터에서 버려진다
