DNS

이름을 주소로

사람은 104.18.3.25 같은 숫자보다 tech-arena.org 같은 이름을 기억하기 쉽습니다. 도메인 이름을 IP 주소로 바꿔 주는 체계가 DNS(도메인 이름 시스템)입니다. 인터넷의 전화번호부라고 할 수 있습니다.

브라우저에 주소를 치면 먼저 DNS로 IP 주소를 알아낸 뒤, 그 주소로 서버에 연결합니다.

문제 1

도메인 이름을 IP 주소로 바꿔 주는 체계를 ＿＿＿라고 합니다.

도메인 이름의 구조

도메인 이름은 점으로 나뉜 계층 구조로, 오른쪽이 위 계층입니다. www.tech-arena.org는 맨 위의 루트(보이지 않음) 아래 최상위 도메인 .org, 그 아래 tech-arena, 그 아래 www 호스트입니다.

.com, .org, .net 같은 일반 최상위 도메인과 .kr, .fr 같은 나라 최상위 도메인이 있습니다. 각 단계의 DNS 서버는 바로 아래 단계를 맡은 서버가 어디인지 알고 있습니다.

예제

mail.school.ac.kr에서 최상위 도메인은?

  1. 오른쪽 끝이 가장 위 계층입니다.
  2. 최상위 도메인은 .kr(대한민국)입니다.
  3. 그 아래 ac(교육 기관), school, mail 순입니다.

답: .kr

문제 2

도메인 이름에서 .org, .kr처럼 맨 오른쪽 부분을 ＿＿＿ 도메인이라고 합니다.

문제 3

www.example.com에서 최상위 도메인은 .＿＿＿입니다.

문제 4

shop.kim.co.kr은 점으로 나뉜 부분이 몇 개일까요?

문제 5

도메인 이름은 ＿＿＿쪽으로 갈수록 위 계층입니다.

이름 찾기 과정

컴퓨터는 먼저 자기 캐시를 보고, 없으면 인터넷 서비스 회사의 DNS 서버(재귀 서버)에 묻습니다. 재귀 서버도 모르면 루트 서버에 '.org는 누가 맡나?'를 묻고, .org 서버에 'tech-arena.org는 누가 맡나?'를 묻고, 마지막으로 tech-arena.org의 담당 서버에 www의 IP 주소를 묻습니다.

찾은 결과는 정해진 시간(TTL) 동안 캐시에 보관해 다음에는 곧바로 답합니다. 그래서 대부분의 DNS 질의는 몇 ms 만에 끝납니다.

예제

캐시가 비어 있을 때 재귀 서버가 www.tech-arena.org를 찾으려면 몇 곳의 서버에 차례로 물을까요?

  1. 루트 서버에 .org 담당을 묻습니다.
  2. .org 서버에 tech-arena.org 담당을 묻습니다.
  3. tech-arena.org 담당 서버에 www의 주소를 묻습니다. 모두 3곳입니다.

답: 3곳

문제 6

DNS 결과를 정해진 시간 동안 저장해 두고 다시 쓰는 것을 DNS ＿＿＿라고 합니다.

문제 7

캐시가 비어 있을 때 재귀 서버가 묻는 순서를 배열하세요.

문제 8

서버에 한 번 묻는 데 20 ms가 걸리면, 캐시가 비어 있을 때 세 곳에 차례로 묻는 데 몇 ms 걸릴까요?

문제 9

DNS 질의는 짧고 빨라야 해서 주로 ＿＿＿를 씁니다.

DNS가 멈추면

DNS 서버가 고장 나면 서버 자체는 멀쩡해도 이름으로 접속할 수 없어 '사이트가 안 열린다'고 느낍니다. 그래서 DNS는 여러 서버에 복제해 운영합니다. 반대로 DNS 답을 가짜로 바꾸면 사용자를 가짜 사이트로 보낼 수 있어 보안에도 중요합니다(챕터 9).

정리: DNS(이름 → IP), 계층 구조(오른쪽이 위, 최상위 도메인), 캐시 → 재귀 서버 → 루트 → 최상위 → 담당 서버, TTL 동안 캐시, 주로 UDP 53번, 복제 운영

문제 10

DNS 서버가 멈추면 서버가 멀쩡해도 ＿＿＿으로 접속할 수 없습니다.

예제

하루에 같은 사이트를 100번 여는데 DNS TTL이 1시간이면, 하루(24시간) 동안 재귀 서버에 새로 묻는 횟수는 최대 몇 번일까요?

  1. 캐시는 1시간 동안 유효합니다.
  2. 1시간마다 최대 한 번 새로 묻습니다.
  3. 하루 최대 24번입니다(100번이 아니라).

답: 최대 24번
