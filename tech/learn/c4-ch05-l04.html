프로그램마다 자기만의 메모리

여러 프로그램이 동시에 실행되면 서로 메모리를 침범하지 않아야 합니다. 그래서 운영 체제는 프로그램마다 0번지부터 시작하는 자기만의 주소 공간(가상 주소)을 주고, 이를 실제 DRAM의 위치(물리 주소)로 바꿔 줍니다. 이를 가상 메모리라고 합니다.

주소 변환은 CPU 안의 메모리 관리 장치(MMU)가 합니다. 프로그램은 자기가 실제 메모리의 어디에 있는지 몰라도 됩니다.

문제 1

프로그램이 쓰는 주소를 실제 메모리 주소로 바꿔 주는 CPU 안의 장치를 ＿＿＿라고 합니다.

페이지

가상 메모리는 주소 공간을 같은 크기의 조각(페이지, 흔히 4 KB)으로 나누어 관리합니다. 운영 체제는 페이지마다 실제 메모리의 어느 칸(프레임)에 있는지를 페이지 테이블에 적어 둡니다.

4 KB = 2¹²바이트이므로, 가상 주소의 아래 12비트는 페이지 안의 위치(오프셋)이고, 나머지 위쪽 비트는 페이지 번호입니다. MMU는 페이지 번호만 페이지 테이블로 바꾸고 오프셋은 그대로 붙입니다.

예제

페이지가 4 KB일 때 프로그램이 1 MB를 쓰면 페이지는 몇 개일까요?

  1. 1 MB = 1024 KB입니다.
  2. 1024 ÷ 4 = 256페이지입니다.

답: 256개

문제 2

가상 메모리를 나누는 같은 크기의 조각을 ＿＿＿라고 합니다.

문제 3

페이지가 4 KB일 때 64 KB 프로그램은 페이지 몇 개일까요?

문제 4

페이지가 4 KB(2¹² B)이면 오프셋은 몇 비트일까요?

문제 5

32비트 가상 주소에서 페이지가 4 KB이면 페이지 번호는 몇 비트일까요?

페이지 부재와 스왑

모든 페이지가 DRAM에 있을 필요는 없습니다. 당장 쓰지 않는 페이지는 SSD 같은 보조 기억 장치에 내려 두고, 필요해지면 가져옵니다. 찾는 페이지가 DRAM에 없는 것을 페이지 부재라고 합니다.

페이지 부재가 나면 운영 체제가 SSD에서 페이지를 가져오는데, DRAM보다 수천 배 느립니다. 메모리가 모자라 페이지를 계속 내렸다 올렸다 하느라 컴퓨터가 거의 멈춘 듯 느려지는 현상을 스래싱이라고 합니다.

덕분에 실제 DRAM보다 큰 프로그램도 실행할 수 있지만, 자주 쓰는 페이지가 DRAM에 다 들어가야 빠릅니다.

예제

DRAM 8 GB인 컴퓨터에서 여러 프로그램이 모두 12 GB를 쓰려 하면 어떻게 될까요?

  1. 8 GB를 넘는 부분은 SSD로 내려 둡니다.
  2. 내려 둔 페이지를 쓸 때마다 페이지 부재가 납니다.
  3. 자주 일어나면 스래싱으로 매우 느려집니다.

답: 일부를 SSD로 내리고, 느려질 수 있다

문제 9

페이지 4 KB, DRAM 16 MB이면 프레임은 몇 개일까요? (1 MB = 1024 KB)

보호

가상 메모리는 보호의 기능도 합니다. 프로그램은 자기 페이지 테이블에 있는 페이지만 볼 수 있어서 다른 프로그램의 메모리를 읽거나 망가뜨릴 수 없습니다. 페이지마다 읽기 전용, 실행 금지 같은 권한도 붙여, 악성 코드가 데이터 영역에서 실행되는 것을 막습니다(챕터 9).

정리: 가상 주소와 물리 주소, MMU, 페이지(흔히 4 KB)와 프레임, 페이지 테이블, 주소 = 페이지 번호 + 오프셋, 페이지 부재와 스래싱, 보호와 권한

문제 10

가상 메모리 덕분에 한 프로그램은 다른 프로그램의 메모리를 ＿＿＿ 수 없습니다.

예제

페이지 4 KB(0x1000)에서 가상 주소 0x3A7C의 페이지 번호와 오프셋은?

  1. 아래 12비트(16진 3자리)가 오프셋입니다: 0xA7C입니다.
  2. 나머지 위쪽이 페이지 번호입니다: 0x3입니다.
  3. 3번 페이지의 0xA7C 위치입니다.

답: 페이지 3, 오프셋 0xA7C
