웹의 대화 규칙

HTTP는 웹 브라우저(클라이언트)와 웹 서버가 주고받는 요청과 응답의 규칙입니다. 브라우저가 'GET /index.html'처럼 요청하면 서버는 상태 코드와 함께 내용을 보내 줍니다.

요청 방식(메서드)에는 자료를 가져오는 GET, 자료를 보내는 POST(글쓰기, 로그인), 고치는 PUT, 지우는 DELETE 등이 있습니다.

문제 1

웹 페이지를 가져올 때 쓰는 HTTP 메서드는 ＿＿＿입니다.

URL

웹 자원의 위치는 URL로 나타냅니다. https://tech-arena.org:443/player.html?c=c4&ch=08 은 규약(https), 호스트(tech-arena.org), 포트(443, 보통 생략), 경로(/player.html), 질의 문자열(?c=c4&ch=08)로 나뉩니다.

질의 문자열은 이름=값 쌍을 &로 이어 서버나 페이지에 정보를 넘깁니다.

예제

https://example.com/search?q=cpu&page=2 에서 경로와 질의 값은?

  1. 호스트 뒤 /search가 경로입니다.
  2. ? 뒤가 질의 문자열입니다.
  3. q는 cpu, page는 2입니다.

답: 경로 /search, q=cpu, page=2

상태 코드

서버의 응답에는 세 자리 상태 코드가 붙습니다. 2xx는 성공(200 OK), 3xx는 다른 곳으로 가라는 안내(301 영구 이동), 4xx는 요청한 쪽의 잘못(404 찾을 수 없음, 403 권한 없음), 5xx는 서버 쪽의 잘못(500 서버 내부 오류, 503 서비스 불가)입니다.

주소를 잘못 쳤을 때 보이는 '404 Not Found'가 가장 유명합니다.

예제

서버 프로그램에 버그가 있어 페이지를 만들다가 멈췄습니다. 어떤 상태 코드가 가장 알맞을까요?

  1. 요청은 올바르지만 서버 쪽에서 문제가 생겼습니다.
  2. 서버 잘못은 5xx입니다.
  3. 500 서버 내부 오류입니다.

답: 500

HTTPS와 페이지 불러오기

HTTP는 내용을 그대로 보내 중간에서 엿볼 수 있습니다. HTTPS는 HTTP를 TLS로 암호화해 내용과 비밀번호를 지키고, 인증서로 진짜 서버인지 확인합니다. 브라우저 주소창의 자물쇠 표시가 HTTPS입니다(챕터 9).

페이지 하나를 여는 과정은 DNS로 IP 주소 찾기 → TCP 연결 → TLS로 암호화 연결 → HTTP 요청 → 응답 받기 → 그림과 스크립트 같은 추가 파일 요청 → 화면 그리기 순입니다. 이 챕터와 앞 챕터의 모든 내용이 한 번에 쓰입니다.

정리: HTTP 요청·응답, 메서드(GET·POST·PUT·DELETE), URL(규약·호스트·포트·경로·질의), 상태 코드(2xx·3xx·4xx·5xx), HTTPS(TLS 암호화, 인증서), 페이지 불러오기 순서

문제 10

웹 페이지를 여는 과정을 차례대로 배열하세요.

예제

왕복 시간이 50 ms인 서버에 처음 HTTPS로 접속합니다. DNS 왕복 1번, TCP 연결 왕복 1번, TLS 왕복 1번, HTTP 왕복 1번이 필요하면 첫 응답까지 최소 시간은?

  1. 왕복이 모두 4번입니다.
  2. 4 × 50 = 200 ms입니다.
  3. 그래서 가까운 서버와 왕복 줄이기 기술이 중요합니다.

답: 200 ms
